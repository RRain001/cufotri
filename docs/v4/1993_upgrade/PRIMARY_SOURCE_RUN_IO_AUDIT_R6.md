# UFOTRI 4.0（1993）P0 R6 — 输入卡、再释放计算边界与逐小时气象文件

**本文件的目标版本是 1993 年 UFOTRI 4.0（KfK 5194）**，并非 1990 年 KfK 4605。1991 年 KfK 4853 仅作为版本沿革对照。以下结论来自 KIT 官方 1993 PDF **§7.4.1（印刷 pp.51–53）、§7.4.9（p.66）、§7.4.10（pp.67–68）与 §8.2（p.69）**，以及 1991 用户手册 §3.4.7（p.34）的实际页面核查。

原始 PDF：[1993 KfK5194](https://publikationen.bibliothek.kit.edu/270034158/3813483) · [1991 KfK4853](https://publikationen.bibliothek.kit.edu/270030531/3813429)。精确字段、位置和未决问题收录于 [R6 原文输入契约 YAML](primary_source_run_io_contract_r6.yaml)。**这些是来源数据，不是启用中的 CUFOTRI 默认配置。**

## 1. 真正影响 1993 数值物理的控制项

| 1993 名称 | 手册默认 | 实际语义 | 影响 |
|---|---:|---|---|
| `BODFAK` | 100 | 最大土壤空气浓度乘以 BODFAK，用作再释放区域源的最小源强判据 | 源截断与计算开销 |
| `NSTOP` | 70 h | 详细再释放计算的最短持续时间，另有计算停止后的土壤库存处理文字 | 再释放时钟及库存 |
| `IFLENG` | 0 | 0=标准面源几何（14 网格点）；1=窄面源（6 网格点，需要专用径向网格） | 几何离散 |
| `Q(NN,J)` | `17*0.,17*1.` | 对每阶段 HT/HTO 相对释放比的历史 Fortran 重复初始化 | 化学形态份额 |
| `Q1(J)` | `17*1.` | 各阶段绝对源强，原文叙述为 Bq/时步/阶段 | 源项 |
| `ZEIT` | 3600 s | 气象记录间隔，手册明确要求 3600 | **小时计算时钟** |
| `CHIMAX` | 1×10⁻¹⁵ Bq·s/m³ | 时间积分空气浓度阈值，也参与食入模块 | 浓度截断 |
| `LT1/LT2/LT3/LT4` | 90/303/455/670 | 两年植被生长季的始末模型日序 | 植物物候 |

`ARAU=0.3 m`、`NJAHRE=1` 以及 `NUKL(1)=HT,NUKL(2)=HTO` 也来自 §7.4.1。手册第 51 页还给出 `BODFAK` 针对 HT、HTO 和建筑尾流情景的**建议值** 1、100、10、0.1。这些是情景建议，不是四套同时激活的默认设置。

特别注意：**`BODFAK` 的判据与再释放源阈值相连，不等于已有程序数值上如何截断已验收**；旧代码是否采用同一尺度和面积积分方式仍须逐项比对。

## 2. 原文自身有待解释的约束与单位

- **`IZFREI`**：1993 §7.4.1 p.52 写出 `0 < IZFREI < 3600`，同页却给默认值 `3600 s`。该项标注只影响打印用的主烟羽浓度持续时间；不应自行把默认值改为 3599 或声称原版一定采用严格不等式校验。
- **`NSTOP`**：原文在 “最低持续时间 70 h” 外还描述再释放程序结束及土壤活度后续处理。现阶段不能从文字直接推出守恒账本或算法重置规则。
- **`RELFA`**：1993 §7.4.9 p.66 文字写相对湿度 `in percent`，但默认值为 `0.5`；这可能涉及旧版内部百分数/比例约定，必须从原代码或可信测试判定，不能预先乘以 100。
- **原 FORTRAN 气象文件**：§8.2 规定每日一条直接访问记录、一天 24 小时、十项数据；未在 R6 证明二进制记录布局、数值字节序或所有输入变量单位与现代 NetCDF 变量一一对应。

四种风险均以 `SOURCE_LIMITED` 或 `UNRESOLVED` 标记。没有自动修正，更没有将其写入物理求解器。

## 3. 1991 已存在的固定气象/再释放分支

1991 KfK 4853 §3.4.7（印刷 p.34）与 1993 KfK 5194 §7.4.9（印刷 p.66）的五项历史默认值一致：

| 输入 | 1991 | 1993 | 说明 |
|---|---:|---:|---|
| `IRFIX` | 0 | 0 | 0=动态计算再释放；1=指定固定再释放 |
| `REFEST` | 5.0 | 5.0 | 固定再释放率，%/h |
| `ITEMPE` | 1000 | 1000 | 固定温度，摄氏度×100 |
| `ISTRBE` | 100 | 100 | 固定辐射平衡，原文写 Watt |
| `RELFA` | 0.5 | 0.5 | 固定相对湿度，百分数/比例约定待核 |

两版文档均指出 `IRFIX=1` 属于开发早期遗留能力，应谨慎使用；1993 p.66 更直接标注 **only recommended for testing**。气象固定模式只有在 `METIN=1`（对应 METEOROL/METPAR）时才读取相关固定参数。因此，**不能把该模式作为 1993 UFOTRI 4.0 推荐生产计算路径**。

## 4. 输出及检查开关不是物理模型参数

1993 §7.4.10（印刷 pp.67–68）涉及 `IFACHS=28`、`IEINR(1:4)=6,8,12,16`、`IZUAUS=0`、`KAUSDR(12)=12*0`、`IPRPLT=0`、`INUKL=2`、`IWRITE=0`、`LWETE=1000`。

这些主要是旧式打印/日志/输出文件控制。特别是 `IWRITE=1` 向逻辑单元 **9** 写入逐天气序列的吸入、皮肤与食入剂量，与此前食物限制机制使用的逻辑单元 **95** 不可混淆。若将 9 和 95 当作同一个输出，会破坏对历史剂量产物的可追溯性。

## 5. 原始逐小时气象文件的十个变量

1993 §8.2（印刷 p.69）规定每日一条气象记录，小时下标 `J=1,...,24`，顺序如下：

`WR(J), IDIFF(J), IRAIN(J), WG(J), ITEMP(J), ISTRB(J), RELF(J), ISOIL1(J), ISOIL2(J), ISOIL3(J)`。

源文字解释气象文件包含 PGT 稳定度、风向、风速、降雨强度、气温、相对湿度、太阳辐射平衡及三层土壤含水量。它还规定：若缺乏土壤水分观测，文件仍需提供占位字段，实际土壤含水量应经 `IBODFX/BODEIN` 模型参数确定。

**重要边界**：这是原始历史文件接口，不是要求当前 ERA5/ISD/WRF 直接存成此二进制格式。对照 P1 的版本化输入契约时，应明确数据时标、代表站点、原始字段编码和单位，不可仅凭相似字段名称推断等价。
